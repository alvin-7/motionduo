MOUSEHOP / INCIDENT + REPAIR / 2026-10-27

右 Shift 已经松开，
释放确认却补回了左 Shift。

两端安装版本 v0.17.19 / dfb532bc。诊断重启后原生状态清空，用户按左右 Shift 对照复现；此次已保存按下、释放、原生注入与系统状态的完整修饰键序列。

二、根因：把按键位图误用成了左右侧证据

系统侧别 flags：右 Shift
按键位图 KeyState：左 Shift 为 true
                ↓ 旧代码把二者直接 OR
凭空补出“左 Shift”设备侧标志
                ↓ 远程只拥有右 Shift
多出的左侧被当成本地键盘输入保护
                ↓ 释放重试
发布左 Shift 标志 → 残留

MacKeySink::modifier_flags 原先对每个 true 的 CGEventSourceKeyState 调用 flags_for(side)，同时添加一般修饰键位和设备侧别位。这次记录证明：对于注入的右 Shift，位图与侧别 flags 可以不一致。旧代码错误地“制造”了一个并不存在于 flags 的左侧键。

该读回合并逻辑来自本分支 39e0558 的修饰键释放确认改动，不是 v0.17.19 的网络查询隔离改动；也不是这次 Windows 松键包丢失。

三、统一修复，不为右 Shift 写特例

  • 左右侧别只取原生 device flags。按键位图不能再创造左侧或右侧设备标志。
  • 位图仍用于保守确认。若 flags 已清空但位图还报告有键按住，只补充 Shift / Control / Option / Command 的一般位，不提前宣布释放成功。
  • 保留已有释放屏障。仍等待有界的异步读回与重试，不延长超时、不无条件清空所有修饰键。
  • 保留真实本地键。Mac 原生 flags 明确表示的本地另一侧或其他修饰键继续保留。远程与本地同一侧同时按住的所有权歧义仍是原有平台限制。

生产改动只在 input-emulation/src/macos.rs::modifier_flags 和 input-emulation/src/macos_keyboard.rs::observed_modifier_flags。没有新增系统查询或后台线程，没有改变协议、心跳、键码映射或鼠标路径。
