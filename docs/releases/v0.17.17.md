# Mousehop 0.17.17

## macOS Ctrl release repair

- Retain remote modifier-up ownership until a bounded asynchronous retry and
  native HID/combined-session readback confirm clear. An accepted native post
  alone is not a release acknowledgement.
- Post an idempotent CGEvent release after older CG pointer events; retry also
  runs if the sender becomes idle immediately after releasing Ctrl.
- Explicitly stamp movement, button/drag and both scroll paths with the current
  remote modifier plan plus distinguishable fresh local modifiers, preserving
  unrelated flags and local opposite-side modifiers.
- Keep unconfirmed releases in cleanup residue on timeout, error or cancellation
  instead of reporting clean. Simultaneous same-side local/remote ownership
  remains ambiguous.
- Windows capture and transport/protocol settings are unchanged.

The captured incident establishes a native/internal release-state divergence.
A stale pointer event is a plausible reassertion source, not a proven exclusive
cause. These changes repair ownership and event-flag coordination; they do not
claim real dual-machine acceptance solely from automated tests.

## Validation and distribution

The repair passed 308 Windows workspace tests (two desktop-dependent tests
ignored), 43 focused modifier tests and 65 native macOS input-emulation tests.
Windows workspace Clippy, native macOS input-emulation Clippy, main-program
all-target check, formatting and diff checks passed. Twelve regressions cover
release readback/fences, stale flags, siblings, re-press, timeout, API failure,
cancellation and multi-modifier cleanup.

Release assets are rebuilt at version 0.17.17; the previous local
0.17.16-ctrl-release-fix packages are not relabeled as 0.17.17. Package provenance,
SHA-256 checksums and final build results accompany the release.

Local Windows installers are unsigned. macOS bundles without Developer ID
credentials use ad-hoc signatures and are not Apple-notarized; replacing a signed
app can require reviewing Accessibility/Input Monitoring authorization. Existing
configuration and TCC permissions are not changed by building or publishing.

Repeated Windows-to-Mac left-Ctrl handoffs, including idle release, motion,
drag/click/scroll and local-modifier coexistence, remain a separate acceptance
step after installation. No patched installation or live acceptance is implied
by this release.
