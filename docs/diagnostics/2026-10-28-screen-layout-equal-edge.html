Mousehop / MyGo Native / 2026-10-28

Equal Shared Edges

Screen thumbnails no longer become smaller merely because one computer has a lower resolution. Left/right neighbors use equal heights; top/bottom neighbors use equal widths. The other dimension scales proportionally, retaining each device's aspect ratio. Equal aspect ratios produce identical rectangles regardless of resolution.

MyGo renderer fixtures at 680 x 420, not screenshots of installed applications.

Interaction

The canvas reserves room for both normalized orientations, keeping the local screen stationary throughout a drag. The remote thumbnail changes size when snapping between horizontal and vertical neighbors. Snap distances compare centers so resizing cannot shift the snap target away from the pointer.

Equal edges make both corner outlines overlap. A slight cross-axis drag selects the corresponding top/bottom or left/right alignment guide; near the center, the existing anchor is retained. All eight side/corner combinations remain selectable without adding controls.

Pointer motion still sends no configuration requests. Drop sends exactly one atomic placement command. Cancellation, timeout rollback, confirmation and peer-switch/deletion protections remain covered by existing interaction tests.

Verification & Boundaries

  • Windows Go suite: 141 passed, including subtests; macOS native Go suite: 133 passed. Go vet passes on both hosts.
  • Tests cover equal-aspect resolution independence, unequal aspect ratios, Win/Mac and portrait geometry, missing/zero geometry, all eight snaps, compact widths and stationary local geometry.
  • Windows icon-bearing debug build and native macOS ARM64 frontend build pass. No new timers, redraw loops or network calls; geometry remains constant-sized arithmetic on existing render/drag events.
  • An initial Windows run failed the unrelated supervisor ready-marker check. The full suite then passed, and that supervisor test passed three consecutive repetitions without changing its source. A readiness-file read/write race is a possibility, not a proven cause of this transient failure.
  • Only frontend geometry/interactions and documentation change. Backend display dimensions, physical input and crossing transforms are unchanged. Real unequal screens still obey their existing overlap rules.
  • Installed applications and previously delivered installers/DMG are untouched. No new test package, installation, commit or publication. Physical installed-application interaction was not re-tested.
