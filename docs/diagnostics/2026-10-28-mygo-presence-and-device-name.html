Discovery, Access Revocation & Local Identity

MyGo native frontend. Existing dirty mygo branch; no installation, application restart, commit or publication performed.

The existing 10:10 test installers and DMG are unchanged. They do not contain these fixes. Updated source/builds use frontend IPC revision 4; the earlier test packages use revision 3.

1. Confirmed: Removing Access Left Sessions Alive

service.rs::remove_authorized_key removed the certificate from the authorization map and updated frontend settings. Existing TLS sessions were not closed. The handshake callback rejects future sessions, but cannot revoke already-authenticated ones.

Reproduced both with two isolated Windows daemons and across physical Windows/macOS hosts using isolated dummy-backend daemons. Before the fix, authorization disappeared but the sender remained alive throughout the three-second disconnect budget and a subsequent four-second observation.

The listener now retires the exact session token and connection slot before awaiting bounded transport close. The emulation task checks current authorization for queued accepts and incoming messages, and disconnects revoked sessions on authorization updates. Existing disconnect cleanup releases emulation state. The service no longer publishes stale Connected/Entered events for a revoked identity.

A separate stale-UI path is corrected: a connection that never entered the screen still emits IncomingDisconnected. The MyGo model also removes revoked incoming live/locked state without clearing unrelated peers.

2. Discovery: In-Place Updates, Not Goodbye/Rejoin

Changing email previously unregistered and immediately re-registered the same service fullname. Pinned mdns-sd 0.19.1 explicitly supports calling register again to update a service. Unregister additionally schedules a delayed goodbye packet, creating an avoidable overlap with the new advertisement. The same fullname is now updated in place; a genuinely different name is still unregistered.

Evidence boundary: the reported long, asymmetric discovery delay was not reproduced. The original cross-host test discovered the later-configured Mac in 1.838 seconds; the fixed test took 0.955 seconds. These are individual observations, not a latency guarantee or proof that the goodbye race caused the user's exact incident.

No new periodic scan, frame timer or high-frequency network polling was added. The existing 30-second network-interface refresh is unchanged.

3. Local Name Replaces the Page Brand

The daemon emits LocalDeviceName using the same helper that constructs its advertised service name. The page header and local screen-layout tile use that authoritative value. Long names remain on one line, with the complete name available on hover. Navigation remains inside both supported widths. Application/window identity, tray and menu-bar branding remain Mousehop.

Revocation blocks control and drops live connectivity. An enabled outgoing device can still retry and request fresh approval; this is not a successful connection. There is no authenticated wire-level revocation-reason message in this patch, so the sender must not claim to know the remote user's intent.
