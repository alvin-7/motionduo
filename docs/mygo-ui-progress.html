只在需要时出现的 Mac 权限入口

补回旧 GTK 页面移除后遗漏的授权引导。缺少输入权限时才出现小卡片；权限齐全时不增加默认选项。启动和回到应用时静默检查，也可点击 Check again，没有前端常驻轮询。

只有点击 Open settings 才请求授权并打开系统页面。先检查辅助功能，再处理输入监听或输入控制；每项每次运行最多请求一次，避免叠加弹窗。系统请求返回不代表授权成功，前端预检也不等于后台恢复；授权后由用户明确选择重启。

后台因撤销权限正常退出时不自动重启；现在会提示输入服务已停止，可从通知区／菜单栏重启。不改变设备授权，不自动开启剪贴板，也不修改独立后台进程的生命周期。

拖动布局，靠近即吸附

直接拖动远端屏幕到本机屏幕的左、右、上、下。靠近角点时自动吸附；例如拖到左上位置，即可贴边并对齐顶部。没有方向按钮或四角按钮。

  • 本机屏幕保持不动，远端屏幕跟随鼠标；提供吸附轮廓、对齐线与角点，距离目标 18 DIP 内精确吸附。
  • 支持上下左右边缘的四角对齐，共八个有效放置位置。多设备时，下拉框只选择要调整的电脑，不代替拖动。
  • 拖动过程中不发送配置；松开后一次保存方向与角点。按 Escape、失焦、切页、断线或在画布外松开均取消。
  • 保存失败或三秒内未收到后台确认时回退，不把预览误当成已生效配置。切页或选择其他设备后仍跟踪原设备的确认；删除设备会立即清理拖拽与待保存状态，防止编号复用时串到新设备。

原生前端 IPC 升为修订 3，支持布局与连接字段各自原子更新；旧预览版后台会被明确拒绝。设备间 DTLS / KCP 协议未变。

释放控制，保留左右键语义

设置页的 Advanced 内可分别选择左右 Ctrl、Shift、Alt / Option、Win / Command，并搜索触发键。支持仅修饰键组合，也保留已有特殊键或多触发键配置，直到用户明确替换。

点击应用才发送修改；恢复默认回到后台内置组合，不是禁用快捷键。墙边兜底释放单独设置像素阈值，0 只关闭兜底，不关闭快捷键。已配置的大于 500 的值不会被旧滑杆上限截断。

等待后台同步后才能编辑；队列失败保留草稿，保存等待回传，三秒未确认会回退并提示。确认超时无需再次点击便会显示错误；没有常驻轮询计时器，也不使用会丢失左右键区别的简化录制器。

CPU 追查结论：观察工具引入了额外开销

更新此前“原因未定位”的结论：本次用 Windows 原生线程栈和 UIAutomationCore 系统事件跟踪查到，Computer Use 的 codex-computer-use.exe 正在反复遍历前台应用的辅助功能树。事件 509 直接记录了查询方 PID 6996 到 Mousehop PID 38392 的调用，不是仅凭 DLL 名称猜测来源。截图不请求文字（include_text:false）也不会停止观察会话的后台查询。

同一前端、同一 Screen layout 页面，观察会话连接时约占单核 8.98%；通过受支持的 Node 会话重置断开观察后，30 秒样本约 0.57%；重新连接观察又升到 10.15%。该组旧后台已退出，因此又新建在线双端夹具复核，避免将重连开销混入常驻判断。
